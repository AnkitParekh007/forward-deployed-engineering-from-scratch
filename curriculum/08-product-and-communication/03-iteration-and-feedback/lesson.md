# Iteration and feedback

## Why this matters
Users report that categories are confusing.

## Learning objectives
- Explain iteration and feedback in your own words.
- Apply the concept to the customer scenario.
- Produce and independently verify the requested evidence.

## Prerequisites
Complete lesson 11-02: Demo storytelling; use synthetic data.

## Concepts
Feedback is input to prioritization, not an automatic feature request. Reproduce issues and decide what to change.

## Build it
1. Read the scenario and identify the input and expected output.
2. Collect five synthetic comments, cluster them and choose one change to test.
3. Verify the result using the success evidence below.

## Real-world scenario
Users report that categories are confusing. An FDE documents assumptions, tests the smallest useful change and reviews the outcome with the workflow owner.

## Common mistakes
- Treating a generated result as verified evidence. Check it independently.
- Using real customer data in a learning demo. Use synthetic records.
- Hiding missing evidence. Document limitations and ask for review.

## Checkpoint
1. Why confirm feedback with evidence?
2. What evidence would show your exercise works?
3. What should you do if the evidence fails?

## Deliverable
A feedback-to-change decision record.
