# Technical communication

## 💡 Why this matters
A stakeholder asks why RAG answers sometimes abstain.

## 🎯 Learning objectives
- Explain technical communication in your own words.
- Apply the concept to the customer scenario.
- Produce and independently verify the requested evidence.

## 🧰 Prerequisites
Complete lesson 10-05: Responsible AI release review; use synthetic data.

## 🧠 Concepts
Explain impact, trade-offs and decisions in plain language; keep implementation evidence available for engineers.

## 🛠️ Build it
1. Read the scenario and identify the input and expected output.
2. Write a two-paragraph update for a manager and a technical note for engineers.
3. Verify the result using the success evidence below.

## 🌐 Real-world scenario
A stakeholder asks why RAG answers sometimes abstain. An FDE documents assumptions, tests the smallest useful change and reviews the outcome with the workflow owner.

## ⚠️ Common mistakes
- Treating a generated result as verified evidence. Check it independently.
- Using real customer data in a learning demo. Use synthetic records.
- Hiding missing evidence. Document limitations and ask for review.

## 🧪 Checkpoint
1. Why state uncertainty?
2. What evidence would show your exercise works?
3. What should you do if the evidence fails?

## 📦 Deliverable
Two audience-specific messages.
