# Demo storytelling

## Why this matters
A customer has five minutes to review a pilot.

## Learning objectives
- Explain demo storytelling in your own words.
- Apply the concept to the customer scenario.
- Produce and independently verify the requested evidence.

## Prerequisites
Complete lesson 11-01: Technical communication; use synthetic data.

## Concepts
A demo should start with a real problem, show the workflow, explain boundaries and finish with measured results.

## Build it
1. Read the scenario and identify the input and expected output.
2. Record a three-minute demo of a synthetic workflow with one failure case.
3. Verify the result using the success evidence below.

## Real-world scenario
A customer has five minutes to review a pilot. An FDE documents assumptions, tests the smallest useful change and reviews the outcome with the workflow owner.

## Common mistakes
- Treating a generated result as verified evidence. Check it independently.
- Using real customer data in a learning demo. Use synthetic records.
- Hiding missing evidence. Document limitations and ask for review.

## Checkpoint
1. Why show a failure path?
2. What evidence would show your exercise works?
3. What should you do if the evidence fails?

## Deliverable
A script and demo evidence.
