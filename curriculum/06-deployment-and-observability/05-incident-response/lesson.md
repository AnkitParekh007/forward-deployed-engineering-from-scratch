# Incident response

## 💡 Why this matters
A demo service has elevated latency.

## 🎯 Learning objectives
- Explain incident response in your own words.
- Apply the concept to the customer scenario.
- Produce and independently verify the requested evidence.

## 🧰 Prerequisites
Complete lesson 09-04: Reliability and degradation; use synthetic data.

## 🧠 Concepts
Triage scope and impact, gather evidence, mitigate, communicate and record follow-up. Avoid premature root cause claims.

## 🛠️ Build it
1. Read the scenario and identify the input and expected output.
2. Analyze a supplied synthetic timeline and draft an update with known facts and next check.
3. Verify the result using the success evidence below.

## 🌐 Real-world scenario
A demo service has elevated latency. An FDE documents assumptions, tests the smallest useful change and reviews the outcome with the workflow owner.

## ⚠️ Common mistakes
- Treating a generated result as verified evidence. Check it independently.
- Using real customer data in a learning demo. Use synthetic records.
- Hiding missing evidence. Document limitations and ask for review.

## 🧪 Checkpoint
1. What should a first customer update contain?
2. What evidence would show your exercise works?
3. What should you do if the evidence fails?

## 📦 Deliverable
An incident summary and action owner.
