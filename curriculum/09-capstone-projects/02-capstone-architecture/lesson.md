# Capstone architecture

## Why this matters
A pilot requires onboarding checklist generation.

## Learning objectives
- Explain capstone architecture in your own words.
- Apply the concept to the customer scenario.
- Produce and independently verify the requested evidence.

## Prerequisites
Complete lesson 12-01: Capstone discovery brief; use synthetic data.

## Concepts
A complete design joins UI, API, local data, model adapter, authorization, validation and evaluation. Keep the demo data synthetic.

## Build it
1. Read the scenario and identify the input and expected output.
2. Draw your component diagram and explain trust boundaries.
3. Verify the result using the success evidence below.

## Real-world scenario
A pilot requires onboarding checklist generation. An FDE documents assumptions, tests the smallest useful change and reviews the outcome with the workflow owner.

## Common mistakes
- Treating a generated result as verified evidence. Check it independently.
- Using real customer data in a learning demo. Use synthetic records.
- Hiding missing evidence. Document limitations and ask for review.

## Checkpoint
1. Where should authorization be enforced?
2. What evidence would show your exercise works?
3. What should you do if the evidence fails?

## Deliverable
Architecture and three trade-offs.
