# Build a simple UI

## Why this matters
An operator needs a ticket queue.

## Learning objectives
- Explain build a simple ui in your own words.
- Apply the concept to the customer scenario.
- Produce and independently verify the requested evidence.

## Prerequisites
Complete lesson 02-05: JSON and HTTP; use synthetic data.

## Concepts
Separate data, presentation and user interactions; render safe text and handle empty states.

## Build it
1. Read the scenario and identify the input and expected output.
2. Create a form and list for synthetic tickets with an empty-state message.
3. Verify the result using the success evidence below.

## Real-world scenario
An operator needs a ticket queue. An FDE documents assumptions, tests the smallest useful change and reviews the outcome with the workflow owner.

## Common mistakes
- Treating a generated result as verified evidence. Check it independently.
- Using real customer data in a learning demo. Use synthetic records.
- Hiding missing evidence. Document limitations and ask for review.

## Checkpoint
1. Why include an empty state?
2. What evidence would show your exercise works?
3. What should you do if the evidence fails?

## Deliverable
A usable keyboard-accessible screen.
