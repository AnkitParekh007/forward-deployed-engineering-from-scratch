# API contracts

## 💡 Why this matters
An onboarding app receives customer records.

## 🎯 Learning objectives
- Explain api contracts in your own words.
- Apply the concept to the customer scenario.
- Produce and independently verify the requested evidence.

## 🧰 Prerequisites
Complete lesson 03-01: Build a simple UI; use synthetic data.

## 🧠 Concepts
An API contract specifies fields, types, errors and status codes. A consumer should not rely on undocumented behavior.

## 🛠️ Build it
1. Read the scenario and identify the input and expected output.
2. Describe POST /customers and validate missing names in a local example.
3. Verify the result using the success evidence below.

## 🌐 Real-world scenario
An onboarding app receives customer records. An FDE documents assumptions, tests the smallest useful change and reviews the outcome with the workflow owner.

## ⚠️ Common mistakes
- Treating a generated result as verified evidence. Check it independently.
- Using real customer data in a learning demo. Use synthetic records.
- Hiding missing evidence. Document limitations and ask for review.

## 🧪 Checkpoint
1. What belongs in a contract?
2. What evidence would show your exercise works?
3. What should you do if the evidence fails?

## 📦 Deliverable
A valid request and a rejected invalid request.
