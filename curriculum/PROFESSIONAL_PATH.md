# 🧭 Zero to FDE: evidence-driven professional journey

The existing 21-day curriculum is the foundation, not a promise of mastery. Learners choose an experience track, complete evidence milestones, and extend their skills using twelve professional modules. A beginner may need months of independent practice; an experienced engineer can use the diagnostic to prioritize gaps.

## 🎓 Choose your path

| Track | Starting priority |
|---|---|
| Foundations explorer | Programming, terminal, Git and reproducible programs |
| Early-career builder | Independent software delivery and tested integrations |
| Customer-facing transitioner | Coding, data fluency and evaluated AI |
| Senior engineering accelerator | Discovery, architecture, evaluation and rollout |
| Principal / field architect | Operational ownership, architecture trade-offs, value and reusable patterns |

Experience only changes recommendations; no lesson is silently marked complete. Evidence remains self-reported, not certification.

## 🏁 Six milestones and proof

| Milestone | Core phases | Evidence |
|---|---|---|
| Understand and build | 1–2 | Field brief, working program and run instructions |
| Ship a useful slice | 3–4 | Customer brief, tested prototype and baseline |
| Design around data | 5–6 | Data mapping, quality report and design decision |
| Build grounded AI | 7–8 | Grounded assistant, evaluation cases and authority boundaries |
| Make delivery dependable | 9–10 | Deployment diagram, trace, runbook and release checklist |
| Deliver and defend outcomes | 11–12 | Demo, case study, measured evidence and retrospective |

## 🧠 Professional depth

| Module | Required portfolio evidence |
|---|---|
| Model internals and token economics | Pipeline diagram and cost assumptions |
| Provider adapters and structured responses | Typed contract, malformed cases and tests |
| Context design and conversation state | Context budget and controlled comparison |
| Retrieval quality and ranking | Labeled benchmark, recall and reciprocal rank |
| Evaluation and release decisions | Stable evaluation dataset, rubric and release decision |
| Tool contracts and supervised workflows | Read-only mock contract and denied-action tests |
| Enterprise data integration | Synthetic reconciliation and data-quality report |
| Deployment environments and handoff | Responsibility matrix and rollback plan |
| Identity, privacy and safe release | Permission matrix and approved-scope tests |
| Telemetry, service economics and reliability | Latency and cost benchmark plus runbook |
| Customer discovery and commercial value | Discovery map, assumptions and hypothetical ROI |
| Principal-level architecture and portfolio defense | Decision record, measured demo and retrospective |

## 🧪 Runnable professional lab

Run `python3 curriculum/assets/pro_lab.py` from the repository root. The lab demonstrates Recall@K, reciprocal rank, hypothetical token cost, pass rate, p95 latency and cost per successful task using two synthetic cases. Extend the fixtures to at least 20 cases and compare two configurations; document limitations and failures before suggesting a release.

## 📅 Learning rhythm

1. Choose the smallest outcome for this week.
2. Study the prerequisite core lessons and the relevant professional module.
3. Build a synthetic artifact and test it independently.
4. Record the observed result, failure cases and limitations.
5. Explain the trade-off as if presenting to a customer; revise the artifact before moving on.

Do not submit customer data, secrets or material covered by an NDA. Label simulated evidence accurately. Track progress locally and export evidence as Markdown.
