# Database design and queries

## 💡 Why this matters
A company stores tasks by account.

## 🎯 Learning objectives
- Explain database design and queries in your own words.
- Apply the concept to the customer scenario.
- Produce and independently verify the requested evidence.

## 🧰 Prerequisites
Complete lesson 06-01: Clean and validate data; use synthetic data.

## 🧠 Concepts
Model entities and relationships, choose indexes based on query patterns, and use transactions for related writes.

## 🛠️ Build it
1. Read the scenario and identify the input and expected output.
2. Design two related tables and query open tasks by account.
3. Verify the result using the success evidence below.

## 🌐 Real-world scenario
A company stores tasks by account. An FDE documents assumptions, tests the smallest useful change and reviews the outcome with the workflow owner.

## ⚠️ Common mistakes
- Treating a generated result as verified evidence. Check it independently.
- Using real customer data in a learning demo. Use synthetic records.
- Hiding missing evidence. Document limitations and ask for review.

## 🧪 Checkpoint
1. What does a transaction provide?
2. What evidence would show your exercise works?
3. What should you do if the evidence fails?

## 📦 Deliverable
Schema and parameterized query result.
