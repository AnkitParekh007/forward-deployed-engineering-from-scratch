# Prompt instructions and context

## 💡 Why this matters
A ticket classifier confuses priority and sentiment.

## 🎯 Learning objectives
- Explain prompt instructions and context in your own words.
- Apply the concept to the customer scenario.
- Produce and independently verify the requested evidence.

## 🧰 Prerequisites
Complete lesson 06-05: ETL and freshness; use synthetic data.

## 🧠 Concepts
Give a model the task, constraints, examples and relevant context. Treat retrieved text as data, not authority.

## 🛠️ Build it
1. Read the scenario and identify the input and expected output.
2. Write a prompt contract and test ten labeled tickets using a local baseline or optional model.
3. Verify the result using the success evidence below.

## 🌐 Real-world scenario
A ticket classifier confuses priority and sentiment. An FDE documents assumptions, tests the smallest useful change and reviews the outcome with the workflow owner.

## ⚠️ Common mistakes
- Treating a generated result as verified evidence. Check it independently.
- Using real customer data in a learning demo. Use synthetic records.
- Hiding missing evidence. Document limitations and ask for review.

## 🧪 Checkpoint
1. What is context?
2. What evidence would show your exercise works?
3. What should you do if the evidence fails?

## 📦 Deliverable
Outputs and error categories.
