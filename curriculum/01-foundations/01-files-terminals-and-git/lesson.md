# Files, terminals and Git

## 💡 Why this matters
Two teammates edit an onboarding prototype.

## 🎯 Learning objectives
- Explain files, terminals and git in your own words.
- Apply the concept to the customer scenario.
- Produce and independently verify the requested evidence.

## 🧰 Prerequisites
Complete lesson 01-05: Your first field brief; use synthetic data.

## 🧠 Concepts
A repository records changes; commits are snapshots. A terminal runs commands in a current directory.

## 🛠️ Build it
1. Read the scenario and identify the input and expected output.
2. Create a local repo, add a README, inspect git diff and commit it.
3. Verify the result using the success evidence below.

## 🌐 Real-world scenario
Two teammates edit an onboarding prototype. An FDE documents assumptions, tests the smallest useful change and reviews the outcome with the workflow owner.

## ⚠️ Common mistakes
- Treating a generated result as verified evidence. Check it independently.
- Using real customer data in a learning demo. Use synthetic records.
- Hiding missing evidence. Document limitations and ask for review.

## 🧪 Checkpoint
1. What does git diff show?
2. What evidence would show your exercise works?
3. What should you do if the evidence fails?

## 📦 Deliverable
A Git log containing one meaningful commit.
