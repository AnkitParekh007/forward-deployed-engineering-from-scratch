# TypeScript essentials

## 💡 Why this matters
A CRM returns inconsistent fields.

## 🎯 Learning objectives
- Explain typescript essentials in your own words.
- Apply the concept to the customer scenario.
- Produce and independently verify the requested evidence.

## 🧰 Prerequisites
Complete lesson 02-02: Python essentials; use synthetic data.

## 🧠 Concepts
Types define expected values, while runtime validation checks untrusted input. An interface is not runtime validation.

## 🛠️ Build it
1. Read the scenario and identify the input and expected output.
2. Define a Contact type and validate unknown data before displaying it.
3. Verify the result using the success evidence below.

## 🌐 Real-world scenario
A CRM returns inconsistent fields. An FDE documents assumptions, tests the smallest useful change and reviews the outcome with the workflow owner.

## ⚠️ Common mistakes
- Treating a generated result as verified evidence. Check it independently.
- Using real customer data in a learning demo. Use synthetic records.
- Hiding missing evidence. Document limitations and ask for review.

## 🧪 Checkpoint
1. Does TypeScript validate JSON at runtime?
2. What evidence would show your exercise works?
3. What should you do if the evidence fails?

## 📦 Deliverable
Invalid records are rejected with a clear message.
